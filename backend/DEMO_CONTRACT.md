对于无歧义的完整已发布名称/别名与显式参数赋值，当前范围策略使用Schema有效的原始赋值及登记的实体角色确定解析输入，避免把功能名称误作对象名称。此路径不适用于自然语言、冲突或否定赋值；所有对象仍通过相同授权解析，不能用参数赋值授予权限。目标、计划和执行前校验继续生效。

`fixture`连接器版本3调用关联数据处理器，`synthetic_states(workspace_id,catalog_id)`持久化模拟写入。草稿文件可下载；金额和排名由处理器计算。陪练在Conversation业务上下文持久化，后续模型扮演客户而不派发业务，结束或换角色退出。通用模型回答与业务汇总分开；只有真实模型可进入该路径。

下文保留旧20项目录的兼容与回归说明；它不再是新演示安装入口，不把历史模型失败退役等同修复。新旧运行数据的实际替换状态以TASKS为准。

## 历史20项目录：业务功能包

`intent_platform.demo.catalog.function_packages()` 是 20 项模拟功能的权威开发包。每包包含业务用途、实体和动作、有限入参与出参 Schema、正例和参数样例、只读/写入属性、错误与未知结果语义、幂等要求及模拟处理器操作代码。`domain_definition()` 定义客户、账户、交易、贷款、产品、持仓、工单与关系；`action_definitions()` 定义定位、查询、列出、统计、创建、冻结。`intent_platform.demo.engine` 在空间隔离的 `demo_states` 中执行筛选、关联、金额统计和状态变更，写操作按 `operation_id` 留存并可对账。模拟客户同名、账户冻结、空贷款、失败和未知结果可复现。模拟用户 `dev-reader` 仅获准客户 C001；这是本地对象授权夹具，不是正式对象授权来源。

## 发布与运行

旧 `POST /api/v2/dev/demo/seed` 仅供显式`env=test`隔离回归，日常开发与正式环境不安装旧目录。Console主入口为“智能体、功能库、运行日志”，设置包含空间管理与模型配置。实体映射和可选接口资料在功能内，业务Skill在组合功能内编辑，测试和编译预览在智能体详情。保存草稿不会改变已发布页面和旧会话。

功能的 `execution_kind` 为 `direct` 或 `composite`，旧定义缺省按direct读取。组合规则包含不可变 `skill_version_id`、精确 `{function_id,version}` 依赖和 `final_output_mapping`；只支持一层组合，依赖必须为直接功能。智能体显式选择的能力用于自主规划；组合的隐式依赖只用于相应规则内部，不扩大调用或对象权限。发布冲突、缺失依赖、读写属性不一致均阻断。

新智能体默认 `routing_strategy=three-layer-v1`；API旧调用缺省legacy，原发布快照不改写。发布固定 `agent-projection-v1` 三层结构、动作、功能、规则、模型与规划策略。管理端 `POST /agents/{id}/compile-preview` 接收当前revision，返回valid、issues及三层projection，不发布、不调用模型。运行时先按当前权限筛选，再由实体及动作层约束候选，规则根据目标、实体、输入及适用条件判断，触发短语仅辅助。每一步按发布语义绑定对象、校验关系/单位/前置条件，派发前再鉴权。无模型时只允许明确标注的工程预览，不把固定输出冒充模型理解。

运行顺序为目标及对象识别、授权功能过滤、Skill 优先匹配、无 Skill 时模型提议、确定性校验、持久计划、逐步业务执行与结果汇总。模型只返回有限 JSON 计划，不能提供接口地址、代码、权限或未发布功能；非法计划最多修正一次，修正期间不派发调用。Demo 上限为 8 个逻辑步骤、5 个批量对象、20 次业务调用及 3 个并行调用。依赖结果引用仅能读取已发布输出 Schema 字段。写操作只能位于最后一步且须确认，已派发写操作 UNKNOWN 时先对账，不能自动重放。新消息、补参、改口或取消使用既有 revision/状态机边界。

INT-019当时发布在 `three-layer-v1` 内固定 `three_layer_prompt_revision=scope-v3`，旧快照缺省为 `scope-v1`；已发布的scope-v2保持对应指令，不改写既有版本。scope-v2及之后版本把函数目标及精确实体/动作词表用于理解，把直接功能备选和组合最终输出边界用于规则匹配；单功能足够时不扩大为更宽规则，读请求不隐含写入。自主计划按最小充分原则保留明确筛选条件，省略未提供的可选参数。实体、规则和计划结构校验共用整轮一次修正预算，不在每个阶段分别重试，额度事务性保存在当前Run，租约恢复及同run补参不会重置。scope-v3要求已接受的用户参数使用字面量或填入plan.inputs，不按裸文本key=value强制覆盖模型语义。当前明确参数绑定范围见顶部智驭说明。拒绝日志提供阶段、固定错误码和受控Schema路径，不保存模型原始响应及业务值。新提示生效须重新发布智能体，历史不可变版本不覆盖。

5 个业务 Skill 是客户资金概览、账户收支分析、客户贷款概览、异常账户核查、客户业务全景，模板在 `intent_platform.demo.skills`。模型动态规划用于无适用规则的任务；适用规则缺参数时补参，不绕过规则。旧 `planner-v1`～`planner-v3` 继续用于相应历史发布；新发布显式采用 `three-layer-v1`。历史 [INT-018 DeepSeek 验证](../docs/project/records/INT-018-deepseek-validation.md) 仅证明当时版本，本次成绩单列 [INT-019记录](../docs/project/records/INT-019-goal-correction.md)。
开发规则链使用获准业务结果生成可读摘要；资金概览明确列示各账户与合计，账户/客户列表在用户端按行显示。旧会话已生成的历史答复按原记录恢复，不改写为新文案。

管理接口在 `/api/v2/management/workspaces/{ws}` 下提供 `/actions`、`/business-skills`、`/model-profiles` 与 `/runs/{run_id}/trace`，独立旧接口保留兼容，菜单按对象内编辑组织。模型配置支持 OpenAI 兼容协议、明确名称和版本、思考模式、服务端加密凭据、连接及结构化输出测试。开发模式显式开启后，ModelPort 可调用 DeepSeek 官网精确Chat Completions地址；非思考请求发送 `thinking.type=disabled`。公网例外只允许服务端审核登记的模拟目录及其子集/扩展，不按数量20判断；自定义真实定义不能借模拟连接器标志外发。业务连接器不获得公网例外，正式模式仍须用获准内网模型。

运行API继续承载消息、问题、确认、取消和恢复。Run/Event/History/SSE/轮询/耗时在服务端统一投影：用户只看最终答复、获准表格/引用/文件和必要交互；`steps=[]`，中间步骤及三层诊断仅管理轨迹可读。最终RESULT保留data摘要，可包含 `components:[{title,component,data,fields:[{label,value}]}]` 展示组件，来源限于组合最终映射或获准直接结果，不承载步骤输入和诊断。有限计划可用 `result_steps` 明确用户请求的输出步骤，含后续仍会引用的先前结果；缺省或null保持旧的未消费结果行为，纯顺序依赖不隐藏输出。组合仍只展示其最终映射，不能通过 result_steps 暴露内部数据。批量结果按持久call_ids与输入位置关联，不依赖数据库扫描或完成先后顺序。最终组件按精确功能版本关联展示定义，同名不串用；结果和附件随最终事件序号持久冻结。附件仅在顶层files数组按授权读取。技术标识用于防重放和恢复，页面不展示。计时接口仅返回整轮处理耗时；等待用户时间单列，未采集不得伪造。历史会话也应用当前用户投影，同时保留创建时的业务发布版本。

空间配置使用服务端可信目录和平台管理员清单。`GET /api/v2/management/platform-context` 返回当前管理能力和可分配身份；`POST /api/v2/management/workspaces` 接收name、administrator_id。分配给其他管理员时返回roles为空，创建者不自动获得该空间数据权。管理员通过现有members接口按可信角色上限增撤成员，不能创建平台管理员。运行令牌始终拒绝管理接口；开发身份只用于本地工程验证。

## 开发演示问题

显式升级现有演示入口使用 `POST /api/v2/dev/demo/seed`，body 为 `{"workspace_id":"ws-dev","routing_strategy":"three-layer-v1"}`。升级保留原应用标识与模型配置，创建新的不可变功能和智能体发布；之后省略策略会保留当前策略。三层演示安装 20 项原子功能及 5 个可见组合封装，`function_count=20`、`composite_count=5`；组合内部固定对应 Skill 和原子版本。未改动的已知旧演示目录可以升级，用户编辑过的定义会阻断覆盖。

自主规划只能选择智能体显式功能，显式组合展开为其固定直接步骤；隐式依赖不会成为独立工具。展开后共同受 8 步、20 调用限制，组合外层不能再次批量或加条件；规则内部仍可有限条件和批量。数量参数在计划及规则步骤中使用 `parameter_units:{字段:来源单位}`，后端按已发布换算规则归一化，不静默假定单位。

- `查询 C001 的所有账户余额，给我做资金概览`：客户 → 账户 → 逐账户余额。
- `张晨的所有账户余额，给我做资金概览`：同名客户暂停选择。
- `对 A001 做收支分析`：暂停补充起止日期；金额由确定性处理器计算。
- `查询 C001 的贷款概览`：合同、余额、还款和逾期。
- `查询 C001 的客户业务全景`：资料、账户、贷款与持仓。
- `对 A002 做异常账户核查，客户 C001，原因：演示状态复核`：先查状态，确认后创建模拟工单；拒绝确认零写入。
- `比较 T001 交易和 A001 账户状态`：无 Skill 时需已配置模型；固定规则预览不会冒充模型规划。

20项各5条开发正例、至少10个复合场景及5规则是本次完整模型开发验证范围，输入错误和模拟失败/未知另验；用例定义不等于已执行通过，实际分母、失败、参数/结果和耗时见本轮记录。它们不是封存金标。银行内网模型、真实身份、接口、宿主和硬件到位后，仍按项目TESTING与真实功能台账独立验收。

混合回答的新策略 scope-v9 将业务汇总输入限定为获准最终结果、显示名称和确定性统计，不传入含一般问题的原始请求或自由文本目标；概念解释单独生成。旧 scope-v1～v8 仍按原快照读取，既有业务结果在解释失败时保留。
