# 受控业务结果契约（E1，本地工程）

## 适用与版本

新发布的非夹具 `FunctionVersion` 必须在功能草稿中提供 `output_schema` 与 `presentation.field_map`，通过当前草稿修订的验证和探测后才能发布。它们随功能版本和 `AgentRelease` 固定；已发布的旧快照不改写。缺少 `output_schema` 的旧版本仍按其原有结果展示协议读取；新增发布不能借此绕过门禁。

`output_schema` 是有限展示契约，不是通用 JSON Schema。根为 `type: object`、`properties`、`required`、`additionalProperties: false`。最多 40 个字段；支持有明确 `maxLength ≤ 16000` 的字符串、整数、有限数字、布尔值、单层对象及有明确 `maxItems ≤ 100` 的数组（可含有限对象行）。投影后的 JSON 最多 256000 字节。未知关键字、无限制字符串/数组、深层结构与类型不符均拒绝。接口返回的额外字段不会进入展示结果。

`presentation.field_map` 为“展示标签 → 顶层输出字段名”，必须恰好覆盖 `output_schema.properties` 且每字段只映射一次。`result_bindings` 仅可引用已获准显示的顶层对象数组；行的 ID 与标签必须是必需的受控字段。`files` 不能作为普通展示字段；仅 `presentation.files_field: "files"` 可允许已有的内联文件协议，文件经大小、类型、名称与 Base64 验证后保存并生成受权下载入口。至少需要一个展示字段或显式文件边界。

INT-019 的一层组合版本仍须提供完整有限输出 Schema，并把每个公开字段映射到精确规则步骤的获准结果路径。组合包装与有限批量允许对象到第 4 层、数组到第 3 层，字段数、每数组上限和总字节限制不变；直接功能保留原有深度限制。组合内部附件暂不自动提升为用户附件；同一计划中独立直接功能的最终获准附件仍可显示和下载。

用户最终 `RESULT` 可附带 `components:[{title,component,data,fields}]`，只取组合显式映射及不被实际结果引用消费的直接输出；单纯 `depends_on` 顺序依赖不会隐藏结果。失败、未知或取消时，可展示的部分结果作为新的持久事件追加，避免断线游标漏读。所有结果、事件、历史及文件读取重新检查功能与已绑定对象权限。

计划的可选 `result_steps` 可保留用户明确请求且仍被下游引用的直接结果，必须引用不重复的本计划步骤；缺省/null保持原语义。组合结果只允许最终字段映射，内部步骤不会因此提升为用户结果。展示定义按功能ID及发布快照取值，不按可重名的业务名称匹配。组件和文件在最终事件创建时冻结，后续核对不得改写已发布序号的事实；旧事件无该字段时才做兼容投影。内部匹配ID不进入用户答复或汇总模型输入。

最终答复文本在写入及用户读取时统一投影：汇总内部标记 `deterministic_balance_totals` 精确转换为业务称谓“账户余额合计”，不删除其他英文业务字段或改动获准组件数据。旧事件仅在读取时适配，不回写历史原文；轮询、SSE、历史恢复与部分结果采用相同规则。此展示修复不改变规划策略、模型提示或发布快照。

### 每个功能的单一答复路径（INT-033）

`presentation.response_mode` 随功能发布版本固定：`structured` 直接呈现获准字段/表格且不调用模型重复归纳；`content` 只读取 `presentation.content_path` 指向的已声明字符串，并按安全Markdown或文本展示；`summary` 由模型根据获准结果归纳，最终事件不再附带同一批结构化结果组件。复合计划使用复合功能的固定策略。

`content_path` 只允许沿输出Schema声明的对象属性路径读取字符串，接口包装对象及未批准字段永不直接序列化展示。旧不可变版本没有新字段时，仅按原Markdown/table组件、唯一Markdown字符串路径或直接对象列表结构有限推断；缺失/非法文本路径不回退到JSON。此规则只调整用户结果展示和模型汇总调用，不改写旧发布、已受理计划或获准输出范围。

## 来源与人工确认

### 当前字段编辑、测试案例与最终答复（INT-029）

新功能以类型字段维护输入和输出；输入对象、列表和日期仍属于服务端支持的有限 Schema，字符串、集合和嵌套深度必须有界。字段重命名或删除需要同步引用或明确阻止，不能只改变页面标签。输出样例仅从同一修订实际成功执行的获准投影显式保存，不能从失败响应、旧修订或文件字节生成。保存案例不改变执行修订或既有发布。

有限输出契约继续决定哪些数据可进入事件、文件、日志、汇总模型和用户读取。最终文字统一为 Markdown，引用与获准文件独立保留；汇总模型失败时以确定性 Markdown 展示已完成获准结果，不重办业务。前端禁止原始 HTML、图片外链和不安全 URL；旧记录也采用同一用户投影。Markdown 展示不会取消内部字段类型或权限约束。

文档组合的最终映射由当轮模型计划提出，必须恰好覆盖组合声明字段且只引用已批准步骤的受控结果路径。校验后的映射随计划保存，重连、恢复和对账不重新生成；旧模板组合仍使用固定版本中的映射。

OpenAPI 3.0.x 的单个明确 2xx `application/json` 对象响应可生成有限草稿，并为缺失的字符串和列表上限填写保守值。来源定位及建议值须由维护者在来源审查中确认。无响应 Schema、多成功形态、不支持的关键字或含文件的复杂形态保留为**可选择但不可发布**的草稿：先人工填写输出 Schema、字段映射和文件边界，再确认和探测。导入报告中的 `output_review_required` 是待确认提示，不代表接口已通过响应契约验证。

## 探测、执行与错误

成功探测只返回获准字段及文件元数据，不返回原始未映射字段或文件字节；结果不符时验证失败，错误不引用原始业务值。成功执行先投影并校验，再写入 `Call.result`、`RESULT` 事件或 `result_files`。审计只记录状态和调用标识。

- 只读调用已确认业务成功，但输出不符：调用和运行状态为 `FAILED`，发出 `OUTPUT_CONTRACT_ERROR`；原始响应、文件均不留存。
- 写调用已确认业务成功，但输出不符：调用和运行状态保持 `SUCCEEDED`，发出 `RESULT_UNAVAILABLE` 与 `result_unavailable: true` 的空结果。该状态不触发业务重发。
- 下游返回 `FAILED` 或 `UNKNOWN`：原始失败体不进入账本或展示。`UNKNOWN` 保持对账策略，不当作业务失败，也不自动重发写入。

本契约的合成回环测试只证明本地边界；真实业务字段、文件授权及银行实例响应仍须在 R1/R2 核对。

## 无业务数据返回（INT-031）

新功能可显式设置 `output_mode: "none"`，同时提供空且封闭的 `output_schema`（`properties: {}`、`required: []`、`additionalProperties: false`）、空展示字段映射，并且不含文件边界、结果绑定或组合最终结果映射。`project_output` 始终投影为 `{}`；连接器的未批准响应体不得保存到调用/事件/文件，也不得传给汇总模型。用户看到的是执行状态，不是下游任意内容。

切换到无输出会先检查结果绑定、文件和组合映射；若仍有引用，必须先调整，不能静默删除。已有发布快照保持原 Schema 和结果行为。没有输入参数时仍以 `{}` 调用，执行身份和对象授权检查不因此跳过。

HTTP 204 只有在没有显式 `success_condition`、`status_path`、`result_path` 或 `operation_id_path` 时才可按状态成功处理。定义了这些响应判定字段却收到无内容的 204 时，不能假定业务成功；写操作维持原未知/核对与不自动重发约束。
