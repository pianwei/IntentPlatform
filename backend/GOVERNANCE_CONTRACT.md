# INT-013.1/.2 finite governance contract

## Current local identity precedence (INT-021)

The local identity contract in [CONTRACT.md](CONTRACT.md) supersedes the historical integration/introspection rules below. Default and production `local` uses active LocalAccount records as the member directory and server-configured platform administrator IDs. Workspace membership and stored role ceilings remain separate; creating an account or assigning another workspace administrator gives no implicit workspace grant to the creator. Anonymous Chat principals are never members.

The integration catalog exposes only `local`; new releases pin `identity_policy.version=local-v1`. Key-derived runtime authority is limited by the owner's current account, membership, application/function grants, Key version and visitor/session binding. Old SSO catalogs and membership-grant JSON are not local identity authorities. Existing old publications/conversations are management-only; identity migration creates a new release preserving original business dependencies. Live revocation still survives publish, rollback and renewal. The development/introspection sections below describe only explicit `legacy-test` fixtures (`env=test`), not a supported mixed production mode.

Only existing server-approved references and roles can be selected. These management APIs never accept a URL, secret, new trust source or arbitrary role. Migration `0005` is additive; existing immutable releases and router/compiler implementations are unchanged.

## Workspace governance

### Workspace directory and lifecycle (INT-022)

`GET /api/v2/management/platform/workspaces?query=&status=active|archived|all&limit=20&offset=0` is platform-admin-only metadata pagination. Names are searched literally; `limit` is 1–100. It returns `{items,total,limit,offset}`. Directory visibility never grants tenant business access.

`GET /api/v2/management/workspaces/{ws}` returns `{id,name,status,revision,archived_at,roles,administrators:[{user_id,username,display_name}],member_count,can_manage,can_open,can_archive,can_rename}` to a current member or platform administrator. `can_manage` means platform metadata authority, `can_open` means active membership in an active workspace. Existing own-workspace listing returns active memberships in active spaces only.

`PATCH /workspaces/{ws}` accepts `{revision,name}` for a platform or workspace administrator. `POST /workspaces/{ws}/archive` and `/restore` accept `{revision}` and require platform authority. These return the updated metadata; stale revisions and invalid repeated transitions return 409. Renaming an archived space is rejected. No permanent deletion is provided.

`POST /api/v2/management/platform/workspaces/{ws}/administrators` accepts `{revision,user_id}` and returns updated metadata. Only a platform administrator can assign or reactivate an administrator within the trusted account/role ceiling. The caller does not gain membership. The compatibility member PUT route also rejects administrator promotion or reactivation by non-platform callers.

`GET /workspaces/{ws}/members/page?query=&status=active|inactive|all&limit=20&offset=0` requires an actual space administrator and returns `{items,total,limit,offset}`. Each item extends the original member shape with `username:null|string,display_name,account_active`. Search uses account/display names. `GET /workspaces/{ws}/members/{user_id}/effective-access` returns `{member,workspace:{id,name,status},roles,permissions:[{key,label,allowed}],agents:[{id,name,allowed,reason}],functions:[...]}`. Resource policy permission is separate from object authorization, which is rechecked at execution. Neither endpoint is a platform-data bypass.

Migration `0014` defaults existing spaces to active, revision 1 and access epoch 0, and existing sessions/tickets/intake jobs to epoch 0. It does not rewrite published versions, conversations or ledger facts. Archive increments the epoch permanently and revokes this space's runtime tokens, sessions and unused tickets. Public metadata/icon/CSP SQL, identity mint/exchange/recovery, runtime history/files/SSE, management business operations, intake and final Worker dispatch all enforce the active space and current epoch.

Archive uses the same workspace transaction lock as admissions, result commits, planning commits and final send authorization. Unsent calls and waiting runs are cancelled; unfinished intake is failed and cannot create a revision after restoration. An already-dispatched call may record its actual result or UNKNOWN, but cannot advance dependencies, summarize via a new model call, or issue a new reconciliation request. Runtime session epochs fence such work even after restoration. Account and Key credentials shared across spaces remain valid; restoring a space preserves all resource revocations and requires fresh runtime identities.

Actual current space administrators retain management-only conversation/run/trace/audit history reads while archived. Platform administrators without that space role only see metadata. Public visitors and owners cannot recover archived runtime history after restoration; they start new isolated runtime identities. Guest database ownership is retained solely so an already-dispatched outcome can still be recorded; HTTP authorization does not rely on that ownership alone.

Prefix `/api/v2/management/workspaces/{ws}`. All responses omit credentials, endpoint URLs and introspection secrets. Runtime tokens cannot access any endpoint in this section.

- `GET /catalogs` (admin/maintainer/publisher): `{integrations:[{ref,label,version,channels,fixture_mode}],resolvers:[{ref,version,object_types}],credentials:[{ref,connector_kind}]}`. Only references approved for this workspace are returned. The existing resolver directory stays compatible.
- `GET /members` (admin): `[{user_id,roles,active,revision,ceiling_roles,server_granted}]`. Includes approved users not yet active in the workspace (`revision:0`). In local mode identities come from active local accounts; account creation does not itself add a membership. Historical fixtures may use a server-provisioned roster.
- `PUT /members/{user_id}` (admin): `{revision,roles:Array<"admin"|"maintainer"|"publisher"|"user">,active:boolean}` returns the member shape. Revisions are optimistic, stale 409. Roles must be a subset of the trusted ceiling. Self-edit is denied, including self-disable; admins cannot alter their own authority. Existing members retain their stored ceilings. A previously unassigned active local account can be explicitly assigned by the workspace administrator. Disabled or de-scoped members cannot regain permissions through login, renewal, old tokens, API access or Worker claims.
- `GET /limits` (admin): `{revision,limits:{max_queued_runs,max_routing,max_execution},ceiling:{...},usage:{queued_runs,routing,execution}}`. `PUT /limits` accepts `{revision,limits:{...}}`; positive integers may only tighten the server ceiling. Lowering limits does not cancel already dispatched work. Empty settings return revision 0 and effective server defaults.
- `GET /runs/{run_id}/attempts` (admin) returns the same attempt shape as the scoped runtime endpoint below. No text, arguments, results or secrets are exposed through timing records.

Current server configuration: `RESOLVERS_JSON` and `CREDENTIALS_JSON` supply safe connector catalogs. `INTENT_WORKSPACE_LIMITS_JSON` maps workspace to the three maximums; absent workspace uses finite defaults 100 queued / 4 routing / 8 execution. Server configuration is the only way to widen these limits.

Only in historical `legacy-test` fixtures, `INTENT_INTEGRATIONS_JSON` maps reference to `{label,version,workspace_ids,channels,origins,agent_ids,user_ids}` with explicit typed arrays and no wildcards; empty agent/user lists deny use. `INTENT_MEMBERSHIP_GRANTS_JSON` may supply the complete trusted roster for a workspace. Neither JSON is a local-mode identity or membership authority.

## Historical test integration selection and live revocation

Agent create/draft adds optional `integration_refs:string[]`. New development applications default to `["development"]`; production defaults empty and enabled channels require approved selected integrations. Existing draft clients omitting this field retain the saved selection. Migrated drafts start empty and require an explicit approved selection before a new publication; their old published releases remain available under the legacy policy below. AgentOut adds `integration_refs`, `published_integration_refs`, `revoked_integration_refs`. The published list is null for a legacy release that predates selection.

Publishing stores exact integration reference/version/grant profiles in `snapshot.identity_policy={version:"integration-v1",profiles:{ref:profile}}`. Draft changes do not change the active release. `POST /agents/{aid}/revoke-integration` body `{integration_ref}` appends a live revocation, returns AgentOut; publisher permission required. Revocation is irreversible through this finite UI and is not cleared by publish or rollback. Grant removal or profile/version change in trusted server configuration also fails closed for the pinned integration. Select a new server-approved reference/version and publish when replacing a revoked integration.

Trusted introspection must return `active: true` as an actual boolean, a nonempty `sub` string, and a strictly typed delegation `{integration_id,workspace_ids,agent_ids,user_ids,origins}`. These are service claims, never supplied by browser request bodies. Session creation/renewal and embed ticket creation/exchange require the actual integration to match both current server approval and the pinned identity policy, channel, user, agent, workspace and (embed) exact host origin. RuntimeSession and one-time Ticket retain that identity binding. Renewing a session using another integration is denied. Management operations also check delegation and integration approval for the actual target workspace. All existing runtime API/SSE/history/files and final Worker dispatch/reconciliation checks apply current integration revocation.

Runtime sessions pin their identity policy. Publishing a different selection alone does not invalidate authorized history under an old release; creating a conversation or reading the current release's runtime metadata still requires approval under that current release. Live revocation applies to both old and new sessions and survives rollback.

Legacy releases without identity_policy retain an explicit legacy mode: only a currently server-approved integration may be used; no unapproved legacy name is grandfathered. Existing development sessions bind `development`; existing introspected sessions preserve their recorded integration ID. Unmappable old identity sessions fail closed. This does not rewrite any old release, confirmation TTL or run revision. Old direct management-token chat paths enforce this same channel/integration policy.

## Distributed limits and per-attempt timing

New-message and answered/confirmed run admission use one PostgreSQL workspace transaction lock and count the actual pending queue across users. A limited database function returns only the authorized workspace aggregate, without widening owner-only Run access. Full queue returns 429 with Retry-After, no new message/run/revision mutation; idempotent repeats return the existing run. Worker routing and outbound execution/status-query slots use that same workspace lock and persistent processing-attempt leases, so multiple worker processes share caps. A lease expired after a dispatched request retains UNKNOWN; no quota operation replays a write. Late responses from expired attempts cannot overwrite a newer claim. New governance and attempt tables enforce FORCE RLS, including against the schema owner.

`GET /api/v2/runtime/runs/{run_id}/attempts` requires the owning conversation's scoped session and current authorization. Response is `[{id,run_id,revision,kind:"routing"|"execution"|"reconciliation",call_id:null|string,status,queued_at:null|timestamp,started_at,finished_at:null|timestamp,lease_until,queue_ms:null|number,context_ms:null|number,model_ms:null|number,validation_ms:null|number,connector_ms:null|number,total_ms:null|number,error_stage:null|string}]`. Each retry/resumption creates a distinct attempt; nothing is overwritten into a fabricated all-zero timing. Skipped or unobserved stages are null. Completed durations use measured monotonic elapsed time; routing queue duration uses persisted admission time. Execution/reconciliation queue start is not observed, so queued_at and queue_ms stay null. connector_ms measures only an actual connector request; authorization failure before dispatch leaves it null. Abandoned lease attempts keep unknown unfinished stage/total durations and an explicit expired state. Administrators can read workspace timing across owners without reading Run text or results. These are engineering observations, not model/hardware performance acceptance.

This package does not add ablation, global administration, secret editing, external identity provisioning, distributed tracing infrastructure, retention jobs or a production capacity claim.
