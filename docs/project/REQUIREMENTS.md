# 一期需求与可观察验收

本文件定义需要证明的行为，不记录任务进度。任务负责人在 [TASKS.md](TASKS.md) 维护实现、验证、集成和交付事实；功能材料与接入状态在 [FUNCTIONS.md](FUNCTIONS.md) 维护，验证方法在 [TESTING.md](TESTING.md)。

当前依据为最新用户要求、[交互与本地账号基线](../../方案/交互重构与本地账号实施基线_2026-09-28.md)及[纠偏基线](../../方案/目标纠偏实施基线_2026-09-24.md)的未冲突部分。下文**主文**指[一期方案V2.1](../../方案/银行内网本体意图中台一期方案_V2.1.md)，**契约**指[路由契约V2.1](../../方案/功能接入与智能体路由契约_V2.1.md)，在与新目标不冲突时适用；REQ-001～014银行真实验收线保留。

## 需求依据的三种性质

- **既定目标**：V2.1 明确陈述的用户目标与边界，包括全内网、隔离空间自助接入至少 20 个真实不同业务功能、语义和动力映射、场景智能体及统一运行界面。属于本项目沿用的工作基线，不代表产品已实现。
- **评审细化**：为证明目标而提出的协议、异常行为、验证配置和执行机制。作为研发展开与验收准备依据；具体环境、存在分歧的规则和关键业务取舍按 [DECISIONS.md](DECISIONS.md) 处理，不把文档写成已获批准的实现事实。
- **建议待冻结**：效果门槛、样本量、性能参数和具体超时等建议值。由对应任务结合真实数据与环境形成决策后冻结；不能自动当作承诺或实测成绩。

REQ 编号是稳定追踪标识，A 编号沿用契约第 9 节。每项后续任务关联相应 REQ 与 A 编号，并链接可重现证据。方案例子中的业务名、接口、ID 和参数不是正式功能清单。

## 量化口径及冻结边界

以下沿用主文 §11 的建议，统一由 DEC-004 关联真实决策和证据。门槛调整需保留来源、理由和影响，不通过降低标准把既有失败改称成功。

| 项目 | 建议待冻结内容 | 不能省略的计分或环境条件 |
|---|---|---|
| S1 | 20 项各 50 条，共 1,000 条单诉求 | 明确、已授权、参数充分；金标含允许功能/等价集合、语义、参数及 READY 或 NEEDS_CONFIRMATION；确认型功能不能排除 |
| S2 | 共 200 条：80 歧义、60 域外、60 权限/隔离 | 各组独立评分，不混入 S1 稀释指标 |
| S3 | 100 个多轮场景 | 补参、实体选择、否定改口、功能切换、结果续接、取消；按完整场景判成功 |
| 路由 | C/N ≥95%；C/A ≥98%；A/N ≥97%；每项 C_i/N_i ≥90% | N 为全部 S1；A 为服务端完成校验及确定功能、参数后返回 READY/NEEDS_CONFIRMATION；C 同时满足允许功能与金标执行/确认状态。A=0 不达标；无端补参、澄清、拒绝、超时进入分母 |
| 语义与参数 | 语义完整正确率 ≥95%；可执行参数正确率 ≥95% | 两项均以全部 S1 为分母；语义包括动作、角色、关系、否定、关键限制，参数包括最终功能、实体及全部必填字段 |
| 边界与多轮 | 应澄清识别率 ≥95%；域外误接受率 ≤2%；S3 完成率 ≥90% | 分别以 80、60、100 为建议分母；域外同时报告整数错误数。权限与隔离遵守 REQ-006 |
| 真实端到端 | 可用测试服务条件下建议 ≥95% | 正确功能、参数、按策略确认、真实业务成功、正确展示同时满足；下游失败计入原始分母。确认前零执行及确认后成功另报 |
| 路由性能 | 5 个持续在途请求、预热 P95 ≤3 秒、P99 ≤5 秒；1/5/10 并发各至少 30 分钟 | 路由计时包含排队、鉴权、快照、全部模型识别/修复与校验；不含用户等待和业务执行。另报首响应、业务结果、最终答案时延；10 并发用于发现饱和点，不自动套用同样时延承诺 |
| 负载与环境 | 固定到达率开放式压测、冷启动、最大历史、接入任务并行 | 5 在途不是 5 RPS；记录版本、硬件、tokens、缓存、历史、吞吐、限流、超时与排队增长，不能删候选或漏计耗时宣称达标 |

数据规模只支持对应样本下的估计；报告样本量和不确定性，不宣称已精确证明生产错误率。开发数据与封存数据按会话和表达族隔离，模型生成样本须经业务核对。
