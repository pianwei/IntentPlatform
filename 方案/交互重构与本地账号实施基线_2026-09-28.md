# 意图中台交互重构与本地账号实施基线

来源：用户于 2026-09-28 批准本轮交互与身份调整，并明确要求先审核三页面预览，再正式集成。关联 INT-021、Demo-13～19、DEC-023～026；实际状态、证据及四项交付事实只在 [TASKS](../docs/project/TASKS.md) 维护。

本文件定义已批准的目标和实施顺序，不证明产品已经具备下述能力。来源顺序为最新用户要求 → 本基线 → [目标纠偏基线](目标纠偏实施基线_2026-09-24.md)及[目标](目标.md)的未冲突部分 → 旧方案未冲突部分。三层路由、功能组合、调用账本和最终结果投影继续保留，不扩大为通用后台或流程引擎。

## 先审三页面预览

第一包只实现独立、本地、可交互的预览入口，不替换当前 `/console/` 默认页面，不连接真实业务、不执行模型调用、不改账号/权限/发布及数据库。预览显示模拟标识，表单校验、切换和发布动作仅改变页面演示状态。

| 页面 | 用户可审核的交互 |
|---|---|
| 智能体首页 | 导航、空间切换、智能体列表、头像菜单及个人中心预览 |
| 会话日志 | 筛选、会话切换、问答轮次、结果概览及阶段展开 |
| 功能编辑 | 分步填写、必填提示、参数编辑、校验和发布预览 |

视觉参考 shadcn-admin 的后台布局、Ant Design 的表单组织与反馈、Langfuse 的会话和轮次结构。预览使用现有 React/lucide 等本地工程能力；参考外观和交互不表示已经引入对应依赖或复制其源码。若后续复用代码，另核对实际来源、许可及依赖影响。不能把未成功的设计工具调用写成设计生成或验收成功。

三页形成可运行结果并完成定向检查后供用户审核。用户已审核本轮三页预览并要求继续全部后续内容；该审核点已满足，不重复申请。后续普通实现按已批准范围执行，实际集成及验证状态由TASKS维护。

## 审核后的产品与身份目标

| 入口或能力 | 目标行为 |
|---|---|
| 后管 `/console/` | 使用本地账号登录。平台管理员建号、停用及重置密码；空间角色与成员授权继续隔离。用户通过头像菜单进入个人中心，普通用户不能操作平台账号管理。 |
| 独立 `/chat/{public_id}` | 面向访客匿名公开，无需后管登录；匿名运行身份仅能访问公开应用批准的能力和自己的会话，不继承管理员或其他访客的权限。 |
| 嵌入 `/embed/{public_id}` | 使用绑定本地用户的集成 Key，由宿主后端换取一次性票据；浏览器仅兑换短期运行身份。Key 所有者当前账号、空间、应用及功能权限实时生效。 |
| 管理日志 | 以会话及其问答轮次组织，提供结果概览和三层阶段展开；保留实际事实、脱敏输入输出和耗时。用户端仍仅显示最终结果和必要交互。 |
| 功能编辑 | 用分步表单、明确必填与参数校验表达直接/组合功能；保留固定版本依赖、最终输出映射、草稿与发布边界。 |

密码使用 Argon2id 哈希保存。普通用户修改自己的密码保留集成 Key；平台管理员重置该账号密码撤销其 Key。账号停用后，账号会话、Key、已有运行身份及相关访问全部失效，恢复读取与新调用也须检查。明文密码、Key 和票据不得进入日志或浏览器长期存储。

平台管理员ID来自服务端受控配置，初始化管理员必须显式指定ID并设置密码，不提供默认密码。普通改密同时使既有密码会话失效。Console刷新使用HttpOnly、SameSite=Strict的专用Cookie；匿名Chat另按应用保存首次仅返回一次的恢复凭据，服务端只存摘要，不保存运行token。匿名访客不创建空间Membership；上述专用恢复凭据不允许恢复Key渠道或其他应用。

Key 是宿主后端凭据，不放入 iframe URL、前端代码或浏览器持久存储。宿主后端生成visitor_id，保存平台换票时返回的runtime_session_id关联，不接受浏览器自报身份或旧会话作授权依据；退出先由宿主后端撤销平台session，再清会话并通知iframe。票据限定应用、宿主来源、nonce、Key版本、visitor/session和有效期并防重放；错误应用及第三方Cookie禁用场景仍须验证。共享同一Key的访客不能互读历史、事件、文件或续接他人会话，Key不扩大所有者当前权限。

新身份统一为local，旧SSO和开发登录运行入口默认关闭；历史回归夹具可显式使用仅限env=test的legacy-test，不作为混合生产身份模式。第一包预览未执行此切换；后续实现、迁移与拒绝路径证据分开记录。

## 旧数据和权限边界

保留旧发布、会话和原始版本记录，供获准管理人员只读查看；不按同名、旧用户 ID 或新 Key 自动接管旧会话，不把旧运行令牌转成新身份。不能改写旧发布以伪装为新身份版本，也不能为了迁移删除历史证据。新身份下的新发布与新会话遵守版本固定、权限撤销、未知写结果不重放等既有规则。

本条调整旧基线中“旧会话继续运行”的适用范围，不追改INT-019及更早版本的当时行为。显式绑定旧user_id只关联管理记录；新建local-v1发布时完整复制原业务依赖，不重写旧发布和会话，也不恢复旧未留存的补参原文。管理只读、旧入口拒绝及回退按[工程契约](../backend/CONTRACT.md)实现；回退不能恢复已撤销账号、Key或权限。

## 工作包与验证

| 工作包 | 范围和退出条件 |
|---|---|
| 1. 交互预览及基线 | 三页面演示可交互；预览定向测试、双应用构建及浏览器检查有证据；文档与 Skills 同步。交付预览供用户审核，账号与真实业务能力不计作完成。 |
| 2. 审核后契约与身份 | 明确本地账号、匿名访客、Key/票据、撤销和旧数据只读契约及迁移；实现权限拒绝、凭据生命周期和隔离。 |
| 3. 审核后界面集成 | 将通过审核的首页、会话日志和功能编辑接入真实管理 API；完成个人中心、账号管理、Chat/iframe 及必要交互。 |
| 4. 完整候选 | 同一候选完成 D 类完整软件、完整 Agent 开发评测、浏览器、身份矩阵、迁移、旧数据兼容与适用恢复；保留失败与未执行项，交付运行说明和已知问题。 |

第一包无后端、身份、业务、模型或提示改动时，验证只覆盖预览交互、原入口不变、构建和浏览器，不机械重跑真实模型或后端全量。身份与公共契约实施至少按 C 类；整个 INT-021 最终按 D 类，不把预览通过当作整体通过。实际测试命令与范围维护在 [TESTING](../docs/project/TESTING.md)，执行事实只入 TASKS 及其引用证据。

每包结束核对目标/范围、接口/使用说明、验证证据和 Skills 影响，记录产出、验证、集成、交付；稳定规范、命令或交付方式改变才更新相应 Skills，不在 Skills 存动态进度。测试成功或失败均先保存报告和必要日志，随即按[清理规则](../docs/project/TESTING.md#测试环境清理)删除本轮独立测试容器、网络、卷；保护主服务、共享资源、备份及历史报告，未创建独立资源则记不适用。

真实银行功能、模型、宿主及硬件仍沿 M1～M3 单独验收。本轮匿名 Chat 与 Key 嵌入不代表银行身份/业务授权已经接通，模拟数据不计真实功能数量，不生成 SHA256 相关检验。
