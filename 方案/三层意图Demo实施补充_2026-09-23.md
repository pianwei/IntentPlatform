# 三层意图 Demo 实施补充

用户于2026-09-23明确要求近期先交付可运行的模拟 Demo，本补充仅调整 Demo 范围，不修改一期 V2.1 的 20 项**真实**功能及 M1–M3 验收条件。工程事实和完成状态以 `docs/project/TASKS.md` 的 INT-018 为准。

Demo 以客户、账户、交易、贷款、产品、持仓、工单构成实体层；以定位、查询、列出、统计、创建、冻结动作及20项已登记模拟功能构成动力层；以五个业务 Skill 和受限模型计划构成策划层。一个智能体发布全部20项模拟功能。Skill 先匹配；无适用 Skill 时，已配置的明确版本模型只提出已授权能力的有限计划，后端验证后才执行。最多8个逻辑步骤、5个批量对象、20次业务调用、3个并行调用；不建设通用图形流程编排或任意 DAG。无模型时只可称规则链工程预览。

管理端在同域 `/console/` 配置实体、动作、功能、业务 Skill、模型和智能体，并可查看三层结构化轨迹；用户端 `/chat/{public_id}` 与 `/embed/{public_id}` 仅显示问答、必要补参/选择/确认、获准业务结果、简化步骤和耗时。两端分开授权和构建，运行令牌不能访问管理接口。版本快照、故障恢复和未知写操作处理沿现有账本及发布机制，不因模拟功能放宽。

技术契约、接口、演示问题与数据来源见 `backend/DEMO_CONTRACT.md`；开发验证与真实验收分界见 `docs/project/REQUIREMENTS.md` 和 `TESTING.md`。实际内网模型、20项真实业务材料、身份与宿主到位后，再按原一期方案联调和验收。
