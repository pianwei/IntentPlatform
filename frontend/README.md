# 意图中台双前端

`console/` 为中文管理控制台，`agent-web/` 为统一智能体独立页与 iframe 页；两者各自生成 Vite 构建产物。共享类型与客户端在 `shared/`。React 18、TypeScript、Vite 5 和 assistant-ui 均在 `package.json` 精确声明，依赖树由 `package-lock.json` 固定。

## 运行

默认交付方式是项目根目录执行 `./scripts/dev.ps1 up`，通过同一网关访问：

- 管理平台：`http://127.0.0.1:5173/console/`
- 已发布应用：`/chat/{public_id}`
- 嵌入应用：`/embed/{public_id}`
- 本地联调宿主：`/console/dev-host.html`（仅开发构建）

两份前端制品独立构建，由同一站点共同托管；用户不需要面对两个端口。`console` 构建基址为 `/console/`，Agent Web 为 `/runtime/`，深层聊天路由由网关回退到同一 Agent HTML。API 使用同源 `/api/v2/`，字段以 `../backend/CONTRACT.md` 的 Application v2 为准。

源码组件调试需要 Node.js 20.10 或更新兼容版本，在本目录运行 `npm ci`、`npm run dev:console`、`npm run dev:agent`。Vite 内部端口 5173/5174 仅为开发工具，不能代替统一网关交付。其 `/api` 和 `/health` 代理默认指向 `http://127.0.0.1:8000`，可通过 `INTENT_API_PROXY` 指定容器 API。

本次主机 npm HTTPS 连接失败后，在 Docker `node:22.16.0-alpine` 中完成依赖安装和检查。当前 `node_modules` 含 Linux 原生依赖，不能当作 Windows Vite 安装使用。通过根目录 Compose 启动，或在该容器挂载本目录运行 npm 命令；切换平台应通过该平台的 `npm ci` 重建依赖。

## 构建与检查

```text
npm test
npm run build
npm run build:development
```

- `build`：默认 production 模式，不显示开发身份、夹具初始化和开发宿主入口；Console 产物不包含 `dev-host.html`。
- `build:development`：显式本地开发模式，供开发后端的演示环境使用；包含开发身份与 `console/dev-host.html`。它仍为优化后的静态构建，不能作为正式生产界面发布。
- 两种构建都会先运行 TypeScript 检查，分别输出 `dist/console/` 与 `dist/agent-web/`。
- 测试使用 Vitest + React Testing Library，覆盖客户端管理/运行边界、401 清理、写请求无自动重放、事件去重与会话隔离、宿主握手、问题修订和确认、空间切换过期响应、草稿 revision 及构建模式边界。此层使用受控响应，不代替真实 API、模型、宿主及硬件验收。

## 本地联调路径

1. 明确使用开发后端及开发构建，用界面里的开发身份登录。
2. Console → 接入准备 → 准备两个开发夹具；这些夹具不计入真实20功能。
3. 功能目录查看映射、保存新草稿、验证和发布；试调用真实接口需勾选测试选项，写操作另需明确允许测试副作用。任何调用仍受后端白名单和凭据授权约束。
4. 场景智能体进入“对话界面 / 访问控制 / 发布与嵌入”。配置欢迎语、主题、本地图标和建议问题；独立/嵌入两种视觉预览均不执行业务。在发布页选择已发布功能与渠道，保存携带 revision 的草稿，再发布。访问名单与渠道即时停用单独保存；发布不会覆盖即时停用。
5. 评测诊断页选择已发布智能体，录入或导入自行提供的 JSON 用例数组（每条含 `text`、`expected_capability_id`），填写标识后调用现有诊断接口。页面显示服务端 `correct / total`、正确率、全部失败/异常、发布版本和原始响应。输入不会自动填入示例金标，诊断结果不替代封存 S1/S2/S3 或真实业务验收。
6. 从发布页打开同源 `/chat/{public_id}`；身份服务适配或开发身份换取限定当前应用的 runtime token，发送请求。历史侧栏来自后端；刷新后重新验证身份可恢复原会话，旧会话继续使用创建时的发布配置。
7. Console 开发宿主页在 `http://127.0.0.1:5173/console/dev-host.html`；选择智能体后完成 Origin/source/nonce 绑定的一次性票据握手。宿主页中的开发受托身份只代替本地联调后端，正式宿主必须自行由可信后端申请票据。页面可切换智能体站点 Origin，宿主 Origin 始终取浏览器实际值，用于 localhost/127.0.0.1 跨来源验证；目标来源仍需匹配 CSP 与已发布允许列表。

## 运行与安全边界

- 令牌只存在于客户端实例内存，使用 Authorization 请求头；不写 URL、localStorage、sessionStorage 或 Cookie。
- iframe 依 `document.referrer` 的实际 Origin 申请握手；无可信来源不登录。父子消息验证精确 Origin、窗口 source、协议、智能体和 nonce；从不用 `*` 传票据。
- sessionStorage 只保存非秘密 runtime_session_id/conversation_id，不能据此访问数据。重新认证后服务端复核身份；恢复读取单次历史快照，再按其 cursor 读取事件，不重发用户消息。同页“恢复会话记录”也重新读取快照以核实发送结果。显式退出清除本地标识并请求服务端撤销。
- 旧问题、旧确认和另一请求的交互禁用，服务端仍是最终授权与状态裁决者。已派发的业务不能被前端取消按钮宣称撤回。
- 内容以受控详情/表格/表单和有限 Markdown 渲染，HTML 不执行、图片不自动加载、链接仅允许无凭据的 HTTP(S)。文件只使用服务端 file ID，通过带当前运行身份的 API 读取后下载；不会导航至模型返回的任意下载地址。引用内容保持服务端原文，未定义结构不虚构来源。

## 已知界限

当前是本地工程基线，不含真实银行功能清单、正式 SSO、真实模型金标评测或正式外围宿主验收。OpenAPI JSON/YAML 导入由服务端有限解析器处理单文档内部引用，支持 GET/POST、标量 path/query/header 和平坦 JSON body；不支持项显示诊断并禁止选择，不抓取外部引用。v2 显式位置映射支持 query 与 body 同时存在，原 v1 不自动改写。复杂定义可在 JSON 映射中显式编辑，最终由后端编译器验证。Dify 与 HiAgent 接入需真实的服务端目标授权、凭据引用、版本及协议映射；未具备时显示验证错误。

预览不调用业务 API；复制的 iframe 代码只加载界面，必须配套实现宿主后端换票、CSRF 防护和退出撤销。界面同时提供可复制握手 JavaScript，并标明宿主端点需要自行实现。未复制 Dify 主项目代码或引入其后端。

发布与回滚操作只调用当前配置的本地 API；本任务未向任何生产环境发布。开发入口、接口代理、宿主 CSP 与正式身份接入必须按真实部署条件配置。

## 领域与评测归档增量

Console 的“领域管理”支持资料来源、概念父类、关系方向、单位与换算草稿，按“保存领域草稿 → 验证领域草稿 → 发布领域版本”操作；发布版本只读。409 冲突保留输入，可复制“当前领域输入快照”与服务器草稿合并。功能管理的“领域语义与实体绑定”须主动选择 v2，再绑定当前空间已发布的精确领域版本；原 v1 不自动升级。角色、参数语义、参数/结果解析器由表单编辑，有限可信前置条件和完整 input_schema 仍需高级 JSON。JSON 与表单共用一份草稿，无效 JSON 会阻止保存和普通表单编辑。解析器目录为空是服务端配置依赖，不提供地址或密钥输入。

运行问题显示服务端问题种类、字段名称和单位；实体/历史选择只提交 opaque option_id，名称描述仍由服务端解析授权。浏览器不转换单位。运行来源只展示后端非秘密绑定摘要。

“评测诊断”页下的“评测结构归档查看”在本地读取冻结格式 trial.json，显示版本、资源声明、全部分母、逐功能、S2/S3 与缺口。下载保留原始字节；格式化展示不用于评分。文件不上传、不入库、不调用业务，不自动作为验收。首次导入只检查可展示结构，不能代替后端严格数据模型校验或真实性核验；20 MB 以上归档使用离线工具查看。

新增定向测试：`npm test -- tests/domain-function.test.tsx tests/semantic-question.test.tsx tests/evaluation-archive.test.tsx`。归档测试可设置 `INTENT_EVALUATION_SAMPLE` 指向只读的既有 PostgreSQL fixture trial.json（必须有 2 个未观测安全步骤），以额外验证真实接口产出的格式及字节保留；默认不依赖本机输出目录。纯前端测试不替代真实模型、资源或浏览器验收。

## 来源文档与服务端接入向导

“来源文档”支持上传新文档、追加修订、选择旧修订、查看抽取原文和章节。追加修订提交目录最新 expected_revision，409 时保留文件选择。原始文件下载仅在 original_available 时提供，通过管理身份读取固定修订；历史文本不会伪装成原文件。

功能目录 → 接入新功能 → “从 OpenAPI 文档接入”：选择来源修订并解析，查看诊断，选择支持的操作，再生成待审查草稿。操作不会调用业务接口。“HTTP 参数位置映射”允许编辑 v2 的 path/query/header/body 映射；重名跨位置保持独立，同位置冲突不会覆盖原字段。

“来源候选、冲突与审查”读取完整 API 事实与人工引用。引用固定文档/修订/章节/逐字摘录；候选解释需人工填写 JSON，不自动变成业务事实。定义与引用一次只编辑一类：定义未保存时可查看来源但不能修改，引用未保存或来源请求进行中时冻结定义编辑，可先保存引用或还原引用修改。保存完整引用列表会增加功能修订。确认理由只确认已保存当前值，任何定义或来源变化都需重新审查。未保存映射/引用、未处理审查及过期修订阻止验证发布；关闭抽屉或切换空间后，迟到响应不会重新打开旧编辑器或覆盖新输入。

导入功能的验证需要已授权环境中的成功与预期 FAILED 两组参数探测；两组 WRITE 探测均需勾选允许写入效果。HTTP2 可显式选择契约约定的业务失败码（400/404/409/422，默认空），并保留必须发送空 JSON body 的约定；不把401/403、5xx或超时当作业务失败。界面传当前 revision、failure_arguments 和 allow_effects，不根据按钮点击宣称通过。字段结构、成功条件、状态/结果路径和有限前置条件仍在高级 JSON 中配置。定向回归：`npm test -- tests/source-import.test.tsx tests/domain-function.test.tsx`。

HTTP2 的表单禁止直接降级到 v1，以免丢失传输约定；需 v1 时创建独立草稿。高级 JSON 中缺少 HTTP 映射分组、分组不是对象或参数名不是字符串时保留原文并阻断表单，修复后恢复编辑。归档的 sanitization 仅作为来源声明展示：已知秘密/线协议字段处理不代表未知秘密已检查，旧归档未提供范围时明确显示未提供。

## 空间治理与可信引用

“空间治理”展示服务端获准的身份集成、实体解析器和凭据引用，不提供地址、密钥或新增信任源输入。空间管理员可编辑服务器名册中的成员、收紧运行限额、按运行标识查询分次尝试的耗时；维护者及发布者只能查看引用目录。自身成员不可修改，角色受服务端上限约束，已被服务端撤销授权的成员只读。409 保留选择或输入；显式重新读取最新设置后，核对新修订和上限再保存。刷新占用只更新查询时的占用快照，保留限额草稿。缺失或 null 的指标显示“未观测”，真实 0 保留为零；这些记录不作为容量、模型或硬件验收。

智能体“访问控制”中选择获准身份集成，随草稿发布；已发布列表和即时撤销独立显示。旧响应未提供选择字段时保存其他配置仍省略该字段，不臆造默认配置。旧版发布明确提示兼容规则，目录候选不等于该应用已实际使用。即时撤销对已有会话生效，发布和回滚不恢复；它只更新撤销状态，不替换未保存草稿或悄悄采用另一个修订。撤销的引用可从草稿移除，不能重新勾选。非 fixture 接入仅标明连接器类型，不代表真实业务验收；已选但停用或缺失的功能保持可见并可移除。

功能编辑的凭据下拉只显示与连接器类型匹配的获准引用；目录为空或未提供时明确说明配置依赖，不填假值。旧引用不在目录时保留原草稿并提示，最终可用性和全部权限由服务端验证。高级 JSON 不绕过服务端信任校验。
