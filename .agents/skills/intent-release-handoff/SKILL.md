# 意图中台版本、交付与反馈

## 读取与判断

交互交付核对弹窗与工作页的同一编辑状态、实际试聊发布版本、偏好旧客户端兼容及空历史过滤；旧记录/快照不因界面变化改写。显示与创建的浏览器证据须对应本次制品，不用前次截图证明本次通过。

以本技能目录向上三级为项目根。读取 [AGENTS.md](../../../AGENTS.md)、[WORKFLOW.md](../../../docs/project/WORKFLOW.md)、本次 [任务](../../../docs/project/TASKS.md)、[验证说明](../../../docs/project/TESTING.md) 及其真实报告。环境/恢复未知项查 [DECISIONS.md](../../../docs/project/DECISIONS.md)，功能快照查 [FUNCTIONS.md](../../../docs/project/FUNCTIONS.md)。

先确定请求是本地移交、候选发布准备、正式部署、回滚还是反馈整理，以及已有授权。不将规范中的发版示例当作当前发布任务。

## 候选与发布

功能及文档Skill候选固定authoring、规划策略、文档与子功能版本，核对当前修订实际测试证据。升级保留旧模板/不可变快照/受理计划；新文档计划及最终映射持久化后恢复不得重新生成。默认目录及展示变化不扩大权限或官网材料白名单，回退不恢复撤权。样例与Markdown材料只含获准字段，不打包模型凭据或原始敏感响应。结果答复策略随功能版本固定；核对结构化/文本内容/模型归纳互斥展示及旧快照有限推断，避免用户答复与业务卡片重复或暴露包装JSON。

1. 从实际工程确定软件版本唯一来源，不把方案V2.1、FunctionVersion、AgentRelease混成软件版本。没有工程配置时记录未建立；没有发版需求时不递增版本/创建Tag。
2. 按本次范围整理候选记录：任务/REQ范围、实际代码或Git提交/Tag/构建编号、功能和AgentRelease、模型标识与参数、提示与本体投影、组件/依赖、评测版本与评分、验证报告、已知问题。不存在的字段写未建立或不适用，不伪造追溯信息。
3. 核实证据对应候选状态。大版本要求完整软件和Agent验证；缺真实环境、失败或未执行的必需项则待验证。只要求准备工作时可以交付缺口清楚的候选说明，但不能称可发布。
4. 准备目标环境、操作顺序、兼容/迁移影响、恢复条件和方法；数据回退与代码回退分别处理。新编译/规划策略上线须保留旧实现与不可变快照，恢复核对功能、依赖、Skill、模型和策略的完整组合，旧依赖缺失明确不可用。旧发布不得恢复已撤销权限；用户历史读取仍遵守当前结果投影。
5. 在已授予范围执行提交、发布或部署。若仍缺必需授权，先完成可审查的候选、验证与执行方案，再只确认剩余动作。环境缺失则交付准备结果及恢复所需条件。
6. 实际部署后验证启动、核心入口、本次功能与相关错误/指标；一期按验收范围检查正式宿主及真实功能。部署命令成功不能单独证明上线可用。

## 移交与反馈

按[交互与本地账号基线](../../../方案/交互重构与本地账号实施基线_2026-09-28.md)交付时，从TASKS核对已有审核和当前候选证据，不重复申请已获授权。身份切换明确local默认、服务端平台管理员ID、无默认密码的初始化、旧SSO/dev拒绝、宿主Key与visitor/session关联的保管方式；不在移交材料写秘密值。提供旧发布/会话原值保留与管理只读、新local身份发布复制原业务依赖、无自动接管、撤销不随回退恢复的证据。初始化账号、数据迁移、发布身份策略、运行服务更新是不同动作。

移交记录交付物位置、可运行步骤、配置引用、验收报告、已知问题、接收范围和实际接收情况。每次维护核对并同步必要文档及Skills，未变化则说明原因。模拟开发候选与银行真实验收分开，界面审核不等于完整候选验收；本地交付不强制等待生产上线。

收到真实问题时关联发生版本/配置、复现材料、影响和需求；按 [规划技能](../intent-project-planning/SKILL.md) 新建后续任务或重开原任务。热修复核对生产基线与开发主线，避免混入未准备功能。重复发生的流程缺口才更新规范并记录理由。

## 状态与完成

按需创建 `docs/project/records/任务ID-release.md`，记录候选准备、验证、实际发布、上线验证、恢复演练分别发生了什么。子执行者返回证据，由当前任务协调者归并TASKS四项事实。

结束条件与用户委托一致。未执行部署写未部署，未达到必需门槛不能写可发布，不能用“发布准备完成”掩盖未完成的上线请求。没有正式监控/调度机制时不承诺离线后继续观察。

## 双端与空间生命周期

包含空间状态的迁移先备份；归档访问代次只能增加，恢复/回退不得复活旧运行身份或已撤销权限。交付同时核对双端资源深链、静态资源与主服务，更新操作说明。动态进度只查TASKS。
# 合成目录替换交付

替换运行目录时，先冻结来源明确的ID与引用清单并验证备份可恢复，再在维护窗口停写和定向事务清理；不删除主卷或共享配置。恢复备份不能重新开放已撤销的旧运行凭据。新应用用新标识、更新宿主关联及访问入口；账号和模型凭据不复制到报告。旧目录失败保留历史，不将退役记为修复或银行验收通过。
