# 意图中台验证与验收

## 输入

从本技能目录向上三级定位项目，读取 [AGENTS.md](../../../AGENTS.md)、[TESTING.md](../../../docs/project/TESTING.md)、本次 [任务](../../../docs/project/TASKS.md) 与 [需求](../../../docs/project/REQUIREMENTS.md)，并检查待验证的真实文件/代码状态、配置和有效证据。专项契约从 [方案入口](../../../方案/README.md) 定位。

阈值冻结情况查 [DECISIONS.md](../../../docs/project/DECISIONS.md)，真实功能与发布成员查 [FUNCTIONS.md](../../../docs/project/FUNCTIONS.md)。按最新已批准产品基线确定本轮范围，模拟Demo与银行真实验收分开；方案数字和示例不是实测结果。

## 选择并执行

1. 明确检查要证明的外部行为。A类做内容/链接/受影响界面检查；B类覆盖局部正常、异常、边界；C类覆盖共享调用方及相关权限/契约/迁移/故障；D类执行完整软件套件、完整Agent评测及适用升级恢复。
2. 应用项目特例：现场第21项接入须测新功能、相邻混淆功能与原20项全量S1；全局模型、本体、提示策略及契约规定的大改扩大至完整回归。小功能小测试不覆盖掉专项要求。
3. 从真实工程配置确认命令、目录、环境与完整套件范围。尚无工程/模型/API时检查能完成的规范或静态部分，列出剩余条件；不得编造执行结果或声称全量通过。
4. 区分软件测试、真实API/模型评测和浏览器宿主验证。需要20功能验收时核对同一智能体的全量发布快照、真实联调与正式iframe；mock和平台预览不作为替代证据。
5. 对照冻结的数据集、金标和评分规则；报告分母、失败、每功能/边界切片、真实下游失败归因、环境和随机波动。不得删除失败样本以提高指标。确认型功能纳入路由集，并额外验证确认前零执行。
6. 动态三层与可插拔功能变更须证明实体/动作在计划前实际参与筛选、规则适用性和步骤语义绑定，检查子集、依赖删除、新增功能和隐式依赖权限；三层日志分区本身不证明三层运行。最终结果投影覆盖用户所有读取通道及旧会话，必要交互保留。
7. 记录通过、失败、未执行、不适用及原因；基线失败与本次引入失败分开。候选状态改变后检查哪些证据失效，再补跑相关项。确认受影响文档与Skills同步，或记录无需修改原因。
8. 成功或失败均先保存报告和必要排错日志，再按 [测试环境清理](../../../docs/project/TESTING.md#测试环境清理) 立即删除本轮独立测试容器、网络和卷，不能只停止。清理前核对归属、挂载与网络使用者，保护主服务、正式数据、归属不明资源、共享镜像、备份及历史报告；既有授权无需再次审批，仅用户明确要求保留现场时例外。记录清理结果，失败记录原因与残留并使自动化入口返回非零，不能以测试通过掩盖清理失败。

## 输出与边界

功能与文档Skill变更核对配置、执行测试和发布三个事实；新修订静态valid、失败/超时/UNKNOWN不得充当执行成功。字段改动须校验结果引用和可信绑定，保存案例只取获准输出。文档规则用实际模型生成计划、动态最终映射及持久恢复证明；拒绝越权依赖、错误类型、循环/非法引用和超预算，写入仍确认且未知不重放。写测试先呈现实际绑定及参数，确认原运行后执行；仅勾选允许副作用不能自动确认模型生成的目标，拒绝及重复确认须证明零额外写入。Markdown展示不得放宽后端投影，HTML/不安全链接不执行；旧模板和已受理计划独立回归，合成目录白名单不因可编辑文档放宽。

结果展示改动验证三种固定路径：结构化结果不再被模型重复总结、内容模式只读取输出Schema中声明的文本/Markdown字段、模型归纳时不再附同一结果组件；用嵌套包装对象及数组结果覆盖。旧发布兼容推断不得暴露未批准字段，非法/缺失内容路径不得降级为原始JSON。

[交互与本地账号基线](../../../方案/交互重构与本地账号实施基线_2026-09-28.md)的预览证据与审核后正式候选分开。账号/Key/匿名及访客隔离至少覆盖C类调用链，整体按D类全量；重点验证匿名无Membership、同Key不同visitor、恢复凭据跨渠道拒绝、刷新单次使用、重置与签发并发、SSE/文件/Worker发送前撤销和已发结果不重放。旧发布/会话管理只读不得写成旧身份继续运行；历史补参未留存不得推造。模型fixture不替代真实模型，浏览器必须实际验证Origin/source/nonce及第三方Cookie禁用。

当前隔离入口见[TESTING](../../../docs/project/TESTING.md)：后端普通套件与三个实际进程故障窗口分别执行；常规pytest中的专项跳过不算该专项通过。测试可显式legacy-test且只能env=test，不能为旧夹具放宽默认local；同空间智能体名称唯一时修正重复名夹具，不删除断言。每次维护核对文档/Skills与真实命令，事实证据交协调者归并。

开发夹具按服务端登记的开发主体绑定目标空间，并重验该空间授权；不得使用无排序目录的第一项作为隐式目标。多空间及撤权回归须证明不改用其他空间，测试准备失败与业务断言失败分开记录。

返回质量结论及证据：对象/版本、命令或人工步骤、环境/数据/配置、期望/实际、结果、报告位置、缺陷与未执行项。复杂记录按需写 `docs/project/records/任务ID-validation.md`；只读评审仅向请求者报告，不自动创建或修改文件。

审查发现应附可定位问题、触发条件、影响和建议；仅审查任务不修改产品。作为子任务时不改TASKS，交协调者更新；独立验证请求由当前协调者统一记录。验收不满足时明确待验证或不通过，不能更改要求让它通过。

全部必需项对当前状态均有成功证据，才称本次范围验证通过；这仍不等于已合并、已上线或人工已批准。大版本完整范围尚未定义时先形成范围清单并标待冻结，不能把已能运行的少量测试称为全量。

## 双端与空间生命周期

配置简化验证选择确认/取消、旧策略保存不变、固定版本关系读取失败、推荐问题编辑/排序及Chat/iframe/预览一致。渠道覆盖关闭前零请求、取消不改草稿、失败不误关、发布不恢复即时停用；回退先查看固定版本，拒绝依赖时保留当前状态。验证弹窗键盘/焦点和旧资源页签兼容，不为仅UI变化重跑未受影响的模型或数据库专项。

创建流程覆盖分步弹窗/展开/补建返回/获取新ID时的状态保持、同修订验证恢复及重复提交；显示偏好覆盖旧字段合并、Portal、字号/密度独立和200%缩放。空会话按实际问答过滤不按标题推测；只恢复已受理业务，不为重绘调用探测或重办。一次性凭据创建与退出需验证交接，试聊核对实际发布版本。

双端版本验证深链/返回/草稿和键盘焦点，空间→成员→权限层级及平台目录不授业务权；归档与发送竞态、已发事实落账、旧凭据永久失效、其他空间不受影响。聊天回答分组不能漏必要交互或重复调用。动态进度只查TASKS。
# 功能编辑重试与目录专项

组合展示及说明模板局部调整验证已选摘要、搜索暂存/确认/取消、旧版本与不可用依赖、模板预览/覆盖保护/追加/只读；查看或取消不能改父草稿。保留精确文档版本重试用例，检查容器切换、未保存保护和窄屏键盘；无运行协议、模型或提示变化不机械重跑未受影响的专项，历史质量问题独立保留。

覆盖Skill草稿保存成功而发布失败、发布响应丢失、发布后版本读取失败及并发发布；重试须绑定所需文档的确切不可变版本，不能偷用旧版或更高的另一文档。业务映射目录须覆盖当前发布的登记引用、未发布草稿不扩充、跨空间与正式环境拒绝模拟引用。

# 合成目录与模型问答专项

功能测试与发布允许不同获准人员分工：发布核验原作者当前授权、同函数修订及真实账本事实，不以发布者身份读取作者私有测试数据。验证原作者撤权后拒绝发布，以及私有测试查询仍拒绝其他发布者。输入嵌套字段改名同步完整路径前置条件及案例；删除被条件引用的字段或祖先必须阻止，不能以顶层测试替代嵌套验证。

分别验证单意图、预设组合、无Skill单目标/多意图规划、独立模型问答，检查真实计划来源和业务调用数；兜底回答不得充当正确路由。覆盖模拟角色切换及恢复、同名消歧、草稿文件、陪练状态、写入确认与未知核对。目录替换验证备份恢复、删除清单零残留、跨表JSON引用、旧凭据拒绝、保留配置不变及中断回滚。首次完整模型结果与修复复测分别保留。

模拟角色切换作为内部权限验证；Chat、iframe和管理试聊不显示身份配置。移除界面选择项时检查默认绑定、既有不同角色历史恢复、确认和陪练控制，确保不切换身份、不额外提交业务；不从UI变化推导重跑未受影响的模型全集。

混合回答须检查段落实际内容及模型输入边界，不能只检查来源标签：业务段仅含获准事实与来源，概念解释另列，解释失败保留已完成业务。自动断言与人工内容复核分开记录；发现断言漏检时保留原报告，增补负断言并复验，不追改原通过分数。

# INT-031业务目录与输出模式

目录验收覆盖平台管理员与空间成员授权、默认版本显式采用与更新、GET无副作用、停用、跨空间拒绝、不可变历史及已发布关系树中的对象→动作→直接功能→固定组合依赖。迁移必须从当前旧版本升级到head并保留既有发布/会话。`output_mode=none`覆盖空Schema、无输入、有限空返回、HTTP204及失败/UNKNOWN分支；断言未经批准的原始响应不进入Call、事件、文件、汇总模型或用户投影，确认/重发策略不变。资料核对UI可按需隐藏，但后端验证和发布阻止仍要覆盖；版本差异与审计关联使用真实version/revision ID，缺失时间或关联不得推测。
