# 意图中台需求与启动管理

## 读取与边界

先读项目根 [AGENTS.md](../../../AGENTS.md)、[BASELINE.md](../../../docs/project/BASELINE.md) 和 [TASKS.md](../../../docs/project/TASKS.md)。项目根由本技能目录向上三级定位；迁移项目时保持相对结构。

范围和验收读取 [REQUIREMENTS.md](../../../docs/project/REQUIREMENTS.md)，计划读取 [ROADMAP.md](../../../docs/project/ROADMAP.md)，缺失事实读取 [DECISIONS.md](../../../docs/project/DECISIONS.md)。[方案入口](../../../方案/README.md)区分当前目标纠偏与银行真实验收；来源优先级是最新用户要求、已批准当前基线、旧方案未冲突部分。

资料是规划输入。区分用户明确目标、评审设计、建议待冻结参数和真实实测；不把本次启动请求扩成未经要求的生产操作。

## 执行

1. 从现有材料提取任务目标、范围和业务验收；不要求用户重新填写已知事实。确认当前是新项目启动、已有需求调整还是规划咨询。
2. 先区分产品纠偏/模拟Demo与银行真实接入。前者按已批准目标推进，真实资源缺口只阻断相应真实验收；后者核对M0的真实20项、负责人、身份、宿主、内网与金标。真实功能进入 [FUNCTIONS.md](../../../docs/project/FUNCTIONS.md)，模拟数据不能填作真实条目。
3. 按 [WORKFLOW.md](../../../docs/project/WORKFLOW.md) 评估A/B/C/D。普通任务保持简短；跨权限、会话、路由契约的取舍记录DEC，不能按代码少降低等级。
4. 更新可观察REQ和相关任务：ID、负责人、依赖、验收、验证计划、目标版本和下一步。共享契约先协调；内部工作包不自动成为多次产品交付，按用户确认的整体交付方式推进。银行阶段继续保留M0–M3真实退出条件，不推算承诺工期。
5. 需求变化记录来源与前后行为，更新受影响的验收、任务、评测及阶段依赖；保留仍有效目标。新增独立产品模块、扩大范围或改变已确认交互先提供用户可审核的范围；已获授权的普通实现不重复审批。具体日期仅在资源确认后登记。

涉及[交互与本地账号基线](../../../方案/交互重构与本地账号实施基线_2026-09-28.md)时，核对TASKS中的三页审核结论，保留预览与正式实现的验收区别；已有审核与继续授权不重复申请。规划身份取舍时分别列本地管理账号、无Membership的匿名Chat、用户Key下的宿主visitor，以及旧数据管理只读。Key不是额外授权，显式旧user_id绑定不是运行历史接管；浏览器专用恢复凭据与访问token的生命周期分别描述。

## 输出与完成

组合规则需求以发布子功能、介绍及Skill文档为维护入口，区分文档驱动模型计划与历史固定模板。默认实体动作和简化界面不等于删掉对象授权、版本固定、关系或单位约束；新功能发布要求当前修订实际执行测试。计划与报告分别列静态检查、执行结果、模型来源、最终输出映射和恢复证据；输出案例不替代Schema。近期模拟产品与银行R1–R3仍分别验收。

替换合成业务目录时区分业务场景数、原子能力数和真实接入数；明确规则链、自主规划及模型直接回答的独立验收。模拟角色是受控数据范围而非平台身份。旧数据清理严格依照当次授权，先备份恢复验证及反向引用盘点，不从替换目录推导删除账号或共享资源。

输出本次需要更新的需求、决策、接入盘点和计划记录，并由当前任务协调者统一归并TASKS。其他子任务只返回建议，不同时写状态。

每次维护检查文档与Skills影响；来源优先级、已确认交互、接口或验证入口变化时同步必要引用和稳定规则，不把本轮测试数量或部署状态存入Skills。

启动规划完成的判据是目标、验收、依赖和可开始事项可检查；有关键未知的产品任务保持待梳理。规范已落地不等于M0完成，少量纵向贯通不等于20功能验收。

缺失的业务规则/资源影响结果时，提出集中且必要的问题并标明受影响任务；继续不依赖它的工作。建议阈值未确认不能声称冻结，旧会话及领域扩展分歧按DEC-008/009处理。仅咨询时提供建议，不自动修改记录或启动开发。

## 双端与空间生命周期

双端交互按空间→成员→权限及对象任务拆分；新建可用完整分步居中弹窗并展开资源页，共享编辑状态；选择使用锚定浮层。字号独立于密度，试聊明确实际发布版本；不将体验优化扩成草稿运行能力。最新明确授权的正式实现不重设原型审核。动态进度只查TASKS。
