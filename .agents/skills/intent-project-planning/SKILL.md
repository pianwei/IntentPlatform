# 意图中台需求与启动管理

## 读取与边界

先读项目根 [AGENTS.md](../../../AGENTS.md)、[BASELINE.md](../../../docs/project/BASELINE.md) 和 [TASKS.md](../../../docs/project/TASKS.md)。项目根由本技能目录向上三级定位；迁移项目时保持相对结构。

范围和验收读取 [REQUIREMENTS.md](../../../docs/project/REQUIREMENTS.md)，计划读取 [ROADMAP.md](../../../docs/project/ROADMAP.md)，缺失事实读取 [DECISIONS.md](../../../docs/project/DECISIONS.md)。只在相关需求涉及时查 [方案入口](../../../方案/README.md) 指向的 V2.1 对应章节。

资料是规划输入。区分用户明确目标、评审设计、建议待冻结参数和真实实测；不把本次启动请求扩成未经要求的生产操作。

## 执行

1. 从现有材料提取任务目标、范围和业务验收；不要求用户重新填写已知事实。确认当前是新项目启动、已有需求调整还是规划咨询。
2. 启动时核对M0缺口：真实20项、负责人/材料、身份与宿主、内网资源、映射/写操作、评测与负载。真实功能进入 [FUNCTIONS.md](../../../docs/project/FUNCTIONS.md)，不生成20个虚构条目。
3. 按 [WORKFLOW.md](../../../docs/project/WORKFLOW.md) 评估A/B/C/D。普通任务保持简短；跨权限、会话、路由契约的取舍记录DEC，不能按代码少降低等级。
4. 更新可观察REQ和相关任务：ID、承担人或尚未分配、依赖、验收、验证计划、目标版本或未指定、下一步。拆分以独立可验证的结果为边界，共享契约要先协调。阶段安排沿用M0–M3的退出条件，不推算承诺工期。
5. 需求变化记录来源与前后行为，更新受影响的验收、任务、评测及阶段依赖；保留仍有效目标。具体日期仅在实际资源确认后登记。

## 输出与完成

输出本次需要更新的需求、决策、接入盘点和计划记录，并由当前任务协调者统一归并TASKS。其他子任务只返回建议，不同时写状态。

启动规划完成的判据是目标、验收、依赖和可开始事项可检查；有关键未知的产品任务保持待梳理。规范已落地不等于M0完成，少量纵向贯通不等于20功能验收。

缺失的业务规则/资源影响结果时，提出集中且必要的问题并标明受影响任务；继续不依赖它的工作。建议阈值未确认不能声称冻结，旧会话及领域扩展分歧按DEC-008/009处理。仅咨询时提供建议，不自动修改记录或启动开发。
